# v0.5.3 异常恢复检测与复核

> 作者QQ：230154231

本版把历史任务的失败与当前异常分开，后续成功证据关闭对应提示，历史记录保留。

## 验证

- 360项后端测试、40项前端逻辑检查全部通过；后端无跳过。
- 新增24项后端恢复回归和5项前端检查，覆盖旧登录恢复、作品已发布、主备用模型、配置切换、无效JSON格式、检测中改变配置、退避、用量、跨域、重复安排、暂停与退出、未知结果不重发、只读回查不进发送流程。
- 本机更新后，旧登录和旧发稿提示由已有成功证据关闭；真实回查及界面结果另见验收摘要。
- 本轮没有新发文章或评论，没有处理私信。自动化单元测试不等同于平台所有场景都通过。

## 代码审查

- GET状态只读本机数据；联网检查作为工作任务执行，不因12秒页面刷新反复调用模型。
- 成功证据绑定相关配置、账号及已失败的任务；新故障不复用旧成功证明。
- 模型探测需要返回合格的业务结构；备用模型成功不能证明主模型恢复。
- 手动恢复检查可以在暂停时执行；自动检测和普通任务保持暂停，退出标志优先。
- 恢复检查不调用登录、发布、发送、批准或公开互动处理流程；作品同步显式使用verify_only，搜索不进入AI分析。
- 评论结果仍未知时保持隔离；同一轮不会因为同时存在读取失败和结果未知而重复读取同一讨论。
- 自动检查仅一项在队列，失败按1/2/5/15/30分钟退避；模型及搜索服从用量上限。
- 配置缺失、额度耗尽与需要核对内容的事项不能通过删除日志或强制隐藏来伪装恢复。

## 使用

修复后，在工作台对应提示点击“重新检测”，或点击“重新检测全部异常”。完成后自动关闭已恢复的提示；尚无恢复证据的项目保留。无需重启。

## 真实只读复核结果

本机v0.5.3中，旧登录和旧发稿提示已由既有成功证据关闭。点击全部重新检测后，自动任务保持暂停；原文读取异常从2段降为1段。2条评论仍未找到唯一的既有发送证据，保持待核对。模型、搜索及发送用量没有新增，发稿提交次数没有新增。
